# Исследование каталога наживок и приманок RF4

Дата проверки: 21 июня 2026 года.

## Вывод

Ручное создание каталога не требуется. В локальном AssetRipper-экспорте уже есть:

- точные внутренние идентификаторы каждого варианта;
- русские названия и описания;
- бренды и семейства товаров;
- отдельные PNG-превью для цветов, размеров и модификаций;
- пути исходных prefab, по которым можно восстановить предметную группу.

До реализации CRUD сначала нужен детерминированный импорт этого снимка и отчет о нераспознанных объектах.

## Что делают другие сайты

- [RF4-STAT](https://rf4-stat.ru/baits/) строит статистический список по фактическим уловам. Изображения загружаются с `img.rf4spot.com` и названы игровыми `systemId`. Это не гарантирует полный каталог: показываются прежде всего предметы, встретившиеся в данных об уловах.
- [RF4PRO](https://rf4pro.com/bait) использует собственный API и поля `id`, `nameRu`, `name`, `imageNamePlain`; изображения запрашиваются по имени файла. Прямой API сейчас требует авторизацию, поэтому он не подходит как стабильный источник импорта.
- [RF4MAP](https://rf4map.ru/) использует наживки в точках и статистике, но не предоставляет открытый полный справочник.
- [Potryasov Game](https://potryasovgame.ru/page110668096.html) дает визуальную классификацию, полезную для сверки категорий, но не является машиночитаемым источником каталога.

Проверка одного изображения показала, что CDN RF4-STAT отдает уменьшенное превью 48x48, тогда как локальный игровой ресурс содержит исходное превью 256x256. Локальная копия качественнее и полнее.

## Рекомендуемая модель

Не следует хранить все в одной текущей таблице `bait`.

1. `tackle_category`: область (`bait`, `lure`, `groundbait`), код категории, название, порядок.
2. `tackle_brand`: системный ID, название, описание.
3. `tackle_family`: бренд, категория, системный ID, название, описание.
4. `tackle_variant`: семейство, `systemId`, полное название, код варианта/цвета, размер, изображение, скрытость.
5. `catalog_import`: версия источника, путь/хеш снимка, время импорта, статистика и ошибки.

Цвет нельзя хранить только как обычное название цвета: игровые коды `001`, `007`, `F006` часто обозначают сложную раскраску. Поэтому нужен строковый `variantCode`, изображение и необязательное человекочитаемое название цвета.

## План импорта

1. Прочитать `ru_RU.bytes` как JSON без ручного редактирования.
2. Собрать whitelist `systemId` из `baits.json` и `lures*.json`.
3. Исключить записи без имени, скрытые и технические prefab.
4. Присоединить `previews/{systemId}.png`.
5. Определить категорию по пути prefab и проверяемой таблице префиксов.
6. Связать вариант с семейством по бренду, внутреннему коду и нормализованному имени.
7. Сформировать отчет: импортировано, пропущено, неизвестная категория, неизвестное семейство, нет изображения.
8. Только после ручной проверки отчета записывать данные в основную БД.
9. Повторный импорт выполнять как upsert по `systemId`, не создавая дубликаты.

## Ограничение

Техническая возможность извлечь игровые названия и изображения не означает автоматического разрешения публиковать графические ресурсы. Перед публичным размещением превью нужно отдельно зафиксировать разрешение правообладателя или допустимый режим использования и атрибуции. Данные и изображения следует учитывать как разные категории материалов.

## Реализованный импорт

Каталог хранится в таблице `bait` с сохранением прежних числовых ID и внешних ключей. Категории, бренды и семейства вынесены в `bait_category`, `bait_brand` и `bait_family`. Игровые записи идентифицируются уникальной парой `domain + system_id`, поэтому повторный импорт не создаёт дубли.

Команды запускаются из папки `back`:

```bash
npm run catalog:dry-run
npm run catalog:import
npm run catalog:import -- --apply
```

Первая команда пересобирает отчёты. Вторая только проверяет подготовленный `items.json`. Третья применяет миграции, выполняет транзакционный upsert и копирует превью в `back/uploads/catalog`. Папка `uploads` не хранится в Git, поэтому на новом сервере импорт с `--apply` нужно запускать при наличии локального экспорта исходных ресурсов.
